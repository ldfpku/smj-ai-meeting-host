## 1. 概述

| 项目 | 内容 |
|---|---|
| 产品名称（候选） | AI 会议主持（内部版），当前代号 SMJAR AI 会议主持人 |
| 目标用户 | 生产制造企业内部会议（≤20 人，≤90 分钟） |
| 核心目标 | 提高会议效率；防止偏题并主动纠偏；自动生成结构化会议纪要；记录决策与待办；支持中英双语 |

**关键约束**

| 约束 | 状态 | 说明 |
|---|---|---|
| 完全自动主持 | 已实现 | 另提供半自动模式，见 3.1 |
| 会前从日历 / 议程文档抓取议题，或手动输入 | 部分实现 | 支持手动输入和 7 个公司标准会议模板。日历与文档抓取未实现 |
| 数据私有化：服务商不得用会议数据训练模型，也不得提供给他人 | 部分实现 | 原始需求为“本地化部署”，2026-09-28 改为本条。纪要整理已改走公司 AI 网关；语音仍发往 Google，各服务商的情况见第 7 节 |
| 偏题提醒 3 秒内触达 | 部分实现 | 开始跑题约 6 秒出现提示，其中 4 – 5 秒是发言人说出第一句闲聊的时间；提示后 0.5 秒主持人开口。发言人不停顿也能打断 |
| 会议结束由专人手动触发生成纪要并校对 | 已实现 | |

## 2. 关键用例

| 用例 | 用户故事 | 状态 |
|---|---|---|
| 自动主持 | 作为会议主持人，我希望 AI 能自动主持（点名、控制发言顺序、计时、打断偏题并引导回议题），以便我专注于决策内容 | 部分实现：计时、点名征询、打断纠偏、催办决议、推进议程可用。发言顺序控制（发言队列）未实现 |
| 偏题干预 | 作为项目负责人，我希望讨论偏离议题时 AI 立即打断并引导回议题 | 已实现 |
| 发言识别与记录 | 作为会议记录员，我希望系统识别并标注发言人、记录讨论要点与行动项并分配负责人 | 部分实现：转写、决议与负责人记录可用。**不能识别发言人** |
| 纪要生成 | 作为会议负责人，我希望会后手动触发生成结构化纪要（决策 / 行动项 / 负责人 / 未解决问题 / 时间线） | 已实现 |
| 离线容错 | 作为 IT 管理员，我希望网络中断时本地缓存数据并在恢复后同步 | 部分实现：会议记录保存在浏览器本机，刷新后不丢失。断网时主持人无法工作，也没有恢复后的同步 |

## 7. 数据、隐私与部署

### 7.1 要求（2026-09-28 确定）

会议数据可以交给云端模型处理，条件是**服务商不把这些数据用于训练模型，也不提供给他人**。
不要求数据留在公司网络内，不要求本地部署。

原始需求写的是“本地化部署（首选）”“默认音频与转写保存在本地”。这两条不再作为要求，
原文保留在附录里供对照。

### 7.2 各服务商的情况

| 数据 | 服务商 | 是否满足 7.1 | 依据 |
|---|---|---|---|
| 纪要整理用的转写全文 | Cloudflare Workers AI（经公司 AI 网关） | 满足 | Cloudflare 文档《Your Data and Workers AI》（2026-04-21 更新）：不把客户内容提供给其他客户，未经明确同意不用于训练模型 |
| 会场语音（实时主持、跑题判断用的识别） | Google Gemini API | **待核实** | 需要确认所用账号的计费档位及其数据条款 |
| 打断语音的文字 | Google Gemini API | **待核实** | 同上。内容只有固定句子和议题名称 |
| 跑题判断用的转写片段 | TypeSafe（Jev） | **待核实** | 尚未查阅其数据条款 |
| 音视频传输、会中消息 | LiveKit Cloud | **待核实** | 尚未查阅其数据条款 |

“待核实”的三家在试点前需要逐一确认。确认不满足的，要么更换服务商，要么改走公司 AI 网关
（可行性见 improvement-plan.md 第 3 节）。

### 7.3 其他要求

| 需求 | 状态 | 说明 |
|---|---|---|
| 密钥不进入浏览器 | 已实现 | 所有模型密钥只在服务端和 agent 端 |
| 纪要整理不在服务商侧留存 | 部分实现 | 走 Gemini 时已设置不留存。走公司 AI 网关时，网关本身不保存请求内容 |
| 会议记录的保存位置 | 部分实现 | 转写、决议保存在浏览器本机。系统不保存音频 |
| 开会前提示数据去向 | 未实现 | 目前开会即发送，没有提示 |
| 访问控制 | 已实现 | 线上地址由 Cloudflare Access 保护，只有名单内的邮箱能凭验证码登录。页面和接口都在保护范围内 |
| 权限管理 | 未实现 | 登录后的人权限相同，任何人都能修改会议配置 |
| 纪要经专人校对后才可见 | 部分实现 | 纪要只在校对人本机生成和导出，没有发布流程 |
| 传输加密 | 已实现 | 全程 TLS |
| 审计日志 | 部分实现 | 记录了每次打断及其撤销（误判）。谁触发了纪要、谁改了配置没有记录 |

## 附录：原始需求

以下是修订前的原文，供对照。

### 概述
**产品名称（候选）**：AI 会议主持（内部版）  
**目标用户**：生产制造企业内部会议（≤20 人，≤90 分钟）  
**核心目标**：提高会议效率；防止偏题并主动纠偏；自动生成结构化高质量会议纪要；记录决策与待办；支持中英双语。  
**关键约束**：完全自动主持；会前可从日历/议程文档抓取议题或手动输入；支持本地化部署与云端模型混合；偏题提醒需在 3 秒内触达；会议结束由指定专人校对纪要（手动触发生成）。

### 关键用例与用户故事
- **用例 1**（自动主持）  
  **用户故事**：作为会议主持人，我希望 AI 能在会议中完全自动主持（点名、控制发言顺序、计时、打断偏题并引导回议题），以便我能专注于决策内容。  
- **用例 2**（偏题干预）  
  **用户故事**：作为项目负责人，我希望当讨论偏离议题时 AI 立即打断并引导回议题，以减少偏题时间。  
- **用例 3**（发言识别与记录）  
  **用户故事**：作为会议记录员，我希望系统能识别并标注发言人、记录讨论要点与行动项并自动分配负责人。  
- **用例 4**（纪要生成）  
  **用户故事**：作为会议负责人，我希望在会议结束后手动触发生成结构化纪要（决策 / 行动项 / 负责人 / 未解决问题 / 时间线），以便快速发布并跟踪执行。  
- **用例 5**（离线容错）  
  **用户故事**：作为 IT 管理员，我希望系统在网络中断时本地缓存数据并在恢复后同步，以保证会议记录完整性。

### 功能清单（按优先级：MVP / v1 / 后续）
#### MVP（首发必须）
- **完全自动主持引擎**：点名、发言队列管理、计时器、轮次分配。  
- **偏题检测与即时干预**：检测偏题并在 ≤3 秒内打断并播报引导语。  
- **语音识别与说话人分离**：中英文 ASR；说话人分离与发言人标注（支持 2–3 人同时说话的鲁棒性）。  
- **结构化实时笔记**：按 决策 / 行动项（含负责人）/ 讨论要点 / 未解决问题 / 时间线 输出草稿。  
- **纪要生成触发**：会议结束后由指定人员手动触发生成最终纪要草稿。  
- **本地缓存与同步**：网络断开时本地缓存音频与中间结果，恢复后自动同步。  
- **桌面或浏览器客户端**：主持控制面板（会前议题、会中控制、偏题提示、发言队列、纪要按钮）。  
- **管理员权限**：组织管理员可配置干预强度与权限。

#### v1（增强与稳定）
- **多模型接入**：支持云端模型（Claude / Google Gemini / system one jev）与本地模型切换策略。  
- **偏题置信度显示**：在会中显示偏题检测置信度（来自 system one jev）。  
- **多语言切换与混合识别**：中英混合识别优化与口音鲁棒性提升。  
- **发言人名录绑定**：支持会前上传参会人员名单以提高说话人识别准确率。  
- **纪要模板管理**：可选多种纪要模板（结构化为主）。  

#### 后续（可选）
- **会议回放与关键片段剪辑**（内部使用）  
- **行动项自动推送到任务系统**（若未来集成）  
- **情绪/参与度分析**（低优先）

### 交互流程与界面要点
#### 会前
- **议题输入**：支持手动输入、从日历/会议邀请抓取、上传议程文档。  
- **参会人员名单**：可选上传以提高说话人识别。  
- **主持策略配置**：管理员/主持人设置干预强度（强制打断 / 温和提示）、语言偏好、ASR 模式（本地/云）。

#### 会中（主持控制面板）
- **左侧**：议题列表与当前议题进度条。  
- **中间**：实时转写与结构化要点流（决策/行动项高亮）。  
- **右侧**：发言队列与计时器；偏题提示弹窗（含置信度条）；“打断并引导”按钮（自动或手动触发）。  
- **交互细节**：当偏题检测触发，AI 自动播报短语并把当前发言者移入“待继续”队列；同时在主持人面板显示偏题原因与置信度。

#### 会后
- **纪要生成**：指定专人点击“生成纪要” → 系统输出结构化草稿（可编辑） → 专人校对后发布。  
- **导出/存储**：支持导出为文本/内部知识库存档（内部使用，不对外）。

### 技术架构与非功能性要求
#### 核心组件
- **音频采集层**：会议室麦克风接入或客户端麦克风；本地降噪预处理。  
- **ASR 与 说话人分离**：优先部署本地 ASR（提高隐私与稳定性），云端模型作为增强选项；采用说话人分离（diarization）模块以支持并发说话。  
- **NLP 层**：主题检测、偏题判定模型、摘要/结构化抽取模型（决策/行动项抽取）。可接入 system one jev 以输出偏题置信度。  
- **主持控制逻辑**：发言队列管理、计时器、打断策略执行器（自动播报/插入提示）。  
- **存储与同步**：本地缓存层 + 后端同步队列；加密存储会议音频与转写（内部部署时可选本地磁盘或企业 NAS）。  
- **前端**：Electron 桌面或 Web 前端（React/Vue），实时通信使用 WebSocket/RTC。  

#### 性能与可用性
- **偏题提醒延迟**：端到端 ≤3 秒（从语音到偏题提示）。  
- **并发与规模**：单次会议 ≤20 人；系统应支持并发若干会议（按内部规模规划）。  
- **鲁棒性**：能容忍 2–3 人同时说话并尽量分离说话人；噪声环境假设较低。  
- **容错**：网络中断时本地缓存并在恢复后自动同步；ASR 失败时降级为人工输入或仅记录音频。

### 数据、隐私与部署建议
- **部署模式**：支持**本地化部署（首选）**与**云端混合**（当需调用 Claude/Gemini/system one jev 时）。  
- **数据流策略**：默认音频与转写保存在本地；仅在明确授权下将必要数据发送云端模型；会后由管理员决定是否保留音频（建议默认 30 天可配置）。  
- **访问控制**：组织管理员权限管理；会议纪要发布需指定专人校对后才可对外可见。  
- **加密与传输**：本地存储加密；云端传输使用 TLS；本地缓存文件加密。  
- **合规**：既然为内部使用且不需额外合规要求，仍建议记录审计日志（谁触发了纪要、谁修改了配置）。

### 验收标准、KPI 与开发里程碑
#### 验收标准（示例）
- **偏题检测**：在真实会议场景中，系统能在 ≤3 秒内对 ≥85% 的偏题片段发出提醒并执行打断策略。  
- **ASR 与说话人分离**：中英文转写字词准确率（WER）达到可接受阈值（内部基线待测）；说话人识别准确率 ≥80%（在有参会名单时）。  
- **纪要质量**：生成的结构化纪要经指定专人校对后，**无需大幅改动**（例如编辑量 <30%）。  
- **稳定性**：本地缓存与恢复机制在网络中断场景下无数据丢失。

#### KPI（表格）
| **指标** | **基线（建议测量）** | **目标** |
|---|---:|---:|
| **会议时长缩短百分比** | 待测 | **≥10%** |
| **偏题发生次数减少** | 待测 | **≥50% 减少** |
| **纪要校对时间** | 待测 | **≤30 分钟** |

#### 开发里程碑（建议）
1. **第 0–2 周**：需求确认、技术选型、原型 UI（主持面板）  
2. **第 3–10 周（MVP 迭代）**：ASR + 说话人分离集成；发言队列与计时器；偏题检测基础模型与自动打断；本地缓存机制；桌面/Web 前端最小可用界面。  
3. **第 11–14 周（内部试点）**：在 2–3 个会议室/团队试点，收集数据与指标。  
4. **第 15–18 周（优化）**：根据试点反馈优化偏题模型、ASR 参数、用户体验与稳定性。  
5. **上线内部推广**：培训管理员与指定纪要校对人。

### 风险与建议
- **ASR 与说话人分离是关键风险点**：建议优先做小规模数据采集（真实会议录音）用于模型微调或选择合适的商用/开源引擎。  
- **偏题判定的误报/漏报**：需设计“可回退”机制（主持人可一键撤销 AI 打断），并在界面显示置信度以便人工判断。  
- **本地部署与云端模型切换复杂度**：建议先以本地 ASR + 云端 NLP（可选）混合方案启动，逐步把敏感处理迁移到本地模型。  
- **用户接受度**：完全自动打断可能引起抵触，建议在初期提供“自动/半自动”两种模式以便平滑过渡（尽管你当前选择完全自动主持，内部推广期可短期开放半自动以降低阻力）。
